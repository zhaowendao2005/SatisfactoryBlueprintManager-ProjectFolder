      process.env.APPDATA || '')

## 📐 项目规范与习惯

### 1. 路径处理规范
- 统一使用正斜杠 `/`（通过 `normalizePath()`）
- 使用 Electron `app.getPath()` 获取系统路径，不使用硬编码或占位符
- 环境变量：Windows 使用 `%LOCALAPPDATA%`、`%APPDATA%`、`%USERPROFILE%`

### 2. IPC 序列化规范
- IPC 传递数据前必须序列化，移除 Vue 响应式代理
- 使用 `JSON.parse(JSON.stringify())` 或手动提取字段

### 3. 配置文件操作规范
- 直接操作磁盘配置文件，然后刷新 Store 状态
- 避免在保存后调用 `switchConfig()`（会先保存当前状态）
- 配置文件操作模式：读取 → 修改 → 保存 → 重新加载 → 更新状态

### 4. 类型文件位置规范
- 跨层级类型（主进程 ↔ 渲染进程）：`public/types/{模块名}/index.ts`
- 导入别名：`@types/{模块名}`
- IDE 警告如不影响运行可忽略

### 5. 日志规范
- 使用标签区分模块：`[SYNC]`、`[FILE-OP]`
- 日志包含：操作类型、路径、数量、耗时、错误信息

### 6. 错误处理规范
- 文件占用检测：超时 5s，失败时提示关闭游戏后重试
- 路径长度检查：Windows 限制 260 字符，超限时跳过并记录错误
- 用户友好提示：将技术错误转换为用户可理解的提示

## ⚠️ 踩的坑与经验总结

### 坑1：IPC 序列化问题
**问题**：传递 Vue 响应式代理对象到 IPC，报错 "An object could not be cloned"

**现象**：
```
Error: An object could not be cloned.
at SyncDatasource.syncLibraryToGame
```

**原因**：Vue 响应式代理对象包含不可序列化的属性（如 `__v_isRef`、`__v_isReactive`）

**解决方案**：在传递到 IPC 前手动提取需要的字段，创建纯对象

**经验总结**：所有通过 IPC 传递的数据都必须序列化，不能直接传递 Vue 响应式对象

---

### 坑2：路径解析问题
**问题**：备份路径使用了 `{userData}` 占位符，但没有被正确解析

**现象**：备份目录出现在项目根目录，路径显示为 `{userData} \ Data \ BlueprintBackup`

**原因**：
- 前端返回了自定义占位符 `{userData}`
- `PathResolver.resolveUserPath()` 只处理环境变量（`%LOCALAPPDATA%`），不处理 `{userData}`

**解决方案**：
- 不使用占位符，直接通过 IPC 调用后端获取 Electron 路径
- 后端使用 `app.getPath('userData')` 获取实际路径

**经验总结**：
- 不要自己写路径占位符
- 统一使用 Electron `app.getPath()` API
- 路径解析统一在后端处理

---

### 坑3：配置文件保存被覆盖问题
**问题**：添加蓝图后，调用 `switchConfig()` 导致新添加的内容被覆盖

**现象**：
```
保存配置文件: test-6498 { treeNodes: 2, fileSize: '8.75 KB' }  ← 添加成功
保存配置文件: test-6498 { treeNodes: 2, fileSize: '7.16 KB' }  ← 被覆盖了！
```

**原因**：`switchConfig()` 会先调用 `saveCurrentConfig()`，保存的是旧的 `treeData`，覆盖了新保存的内容

**解决方案**：
```typescript
// ❌ 错误做法
await configDatasource.saveConfig(configData)
await activeBlueprintStore.switchConfig(targetConfigId)

// ✅ 正确做法
await configDatasource.saveConfig(configData)
const freshConfigData = await configDatasource.loadConfig(targetConfigId)
// 直接更新状态，不调用 switchConfig
activeBlueprintStore.treeData = freshConfigData.tree
```

**经验总结**：
- 操作配置文件后，直接重新加载并更新状态
- 避免调用 `switchConfig()`（会先保存当前状态）
- 参考蓝图源的操作方式：直接操作磁盘文件 → 直接更新状态

---

### 坑4：同步模式选择实现困难
**问题**：最初使用输入框让用户输入模式，但实现复杂且易出错

**原因**：文本输入需要验证、错误处理，用户体验差

**解决方案**：改为使用 Vue 的 `h()` 函数渲染 `el-radio-group` 单选按钮

**经验总结**：
- UI 交互优先选择组件而非文本输入
- 使用 Vue 的 `h()` 函数可以实现动态组件渲染

---

### 坑5：路径拼接错误
**问题**：存档路径和蓝图路径拼接错误，导致打开目录和保存路径不一致

**原因**：路径拼接时未正确处理，或使用了错误的路径解析方法

**解决方案**：
- 统一使用 `path.join()` 拼接路径
- 存档完整路径 = `{basePath}/{selectedSave}`
- 确保打开目录和保存使用相同的路径

**经验总结**：路径拼接要仔细，确保各个操作使用相同的路径计算逻辑

---

### 坑6：游戏→库同步逻辑过于复杂
**问题**：最初设计支持多种模式（diff、full、latest、new-version），实现复杂

**原因**：需要检测文件修改、比较时间、处理冲突等，代码量大且易出错

**解决方案**：
- 简化为只检测新增蓝图（不在索引中的）
- 用户选择蓝图源，批量添加到配置
- 移除复杂的模式判断

**经验总结**：
- 优先实现简单可用的版本，再逐步完善
- 用户需求可能不需要那么复杂的功能
