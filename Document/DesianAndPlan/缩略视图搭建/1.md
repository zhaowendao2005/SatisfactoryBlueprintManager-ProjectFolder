# 快速访问窗口（QuickAccess Window）设计方案

## 📋 第一部分：设计概览

**【目标】**：创建一个独立的轻量级快速访问窗口，供用户在游戏过程中快速筛选和使用蓝图

**【范围】**：
- **在范围内**：
  - 创建独立Electron窗口（QuickAccessWindow）
  - 桌面布局视图展示（复用现有BlueprintDesktopIcon组件）
  - 标签筛选器（订阅GlobalTags Store）
  - 最近使用蓝图记录（记录最近10个使用的蓝图，顶部置顶显示）
  - 全局快捷键唤出/隐藏
  - 托盘菜单集成
  - 通用设置中的快捷键配置
  - 窗口置顶（Always on Top）功能
  - 使用蓝图后自动隐藏窗口（可配置）
  
- **不在范围内**：
  - 蓝图编辑功能
  - 标签创建/删除功能
  - 配置切换功能
  - 独立的数据持久化（完全订阅主窗口）

**【技术栈决策】**：
- 窗口管理：Electron BrowserWindow（原因：需要独立的窗口实例）
- 数据同步：Electron IPC + SharedWorker模式（原因：需要双向实时同步GlobalTags状态）
- 状态管理：Pinia Store + IPC订阅模式（原因：与主窗口共享GlobalTags状态）
- 快捷键：electron.globalShortcut API（原因：需要全局快捷键支持）
- UI框架：Quasar + Element Plus（原因：复用现有组件）

**【架构模式】**：订阅者模式（Subscriber Pattern） + 代理窗口模式（Proxy Window Pattern）

**【核心约束】**：
- 窗口尺寸：宽度400-600px（可调整），高度600-800px（可调整），默认500x700px
- 启动时间：<500ms（从快捷键触发到窗口显示）
- 内存占用：<50MB（窗口创建后）
- 窗口行为：始终置顶（可选），失焦后不自动关闭
- 数据延迟：主窗口数据变更后<100ms同步到快速访问窗口

  y?: number                 // 窗口Y坐标（可选，用于恢复位置）

 * 快速访问窗口服务（Electron主进程）
 * @注意事项 单例模式，全局仅一个实例

class QuickAccessWindowService {
  private quickAccessWindow: BrowserWindow | null
  private mainWindow: BrowserWindow
  private config: QuickAccessConfig
  
  /** 创建快速访问窗口（不显示） */
  create(mainWindow: BrowserWindow, config: QuickAccessConfig): Promise<void>
  
  /** 显示窗口（创建后首次显示或从隐藏状态恢复） */
  show(): void
  
  /** 隐藏窗口（不销毁） */
  hide(): void
  
  /** 切换显示/隐藏 */
  toggle(): void
  
  /** 更新配置（alwaysOnTop等） */
  updateConfig(config: Partial<QuickAccessConfig>): void
  
  /** 销毁窗口 */
  destroy(): void
  
  /** 获取窗口是否可见 */
  isVisible(): boolean
}

/**
 * 快速访问Store状态（前端）
 * @注意事项 只读Store，所有数据来自IPC订阅
 */
interface QuickAccessState {
  tags: TagDefinition[]                        // 全局标签列表（订阅自主窗口）
  blueprintTagsMap: Map<string, string[]>      // 蓝图-标签映射（订阅自主窗口）
  activeFilters: Map<string, 'and' | 'or' | 'not'>  // 当前激活的筛选标签
  recentBlueprints: Array<{ path: string; timestamp: number }>  // 最近使用的蓝图列表（最多10个）
  viewConfig: {
    iconsPerRow: number                        // 每排图标数，默认4
    iconSize: number                           // 图标大小，默认64px
  }
  isSubscribed: boolean                        // 是否成功订阅主窗口数据
  lastSyncTime: number                         // 最后同步时间戳
}

 * 快速访问Store（前端）
 * @注意事项 不提供写操作，所有修改通过IPC转发给主窗口

class QuickAccessStore {
  state: QuickAccessState
  
  /** 初始化并订阅全局标签（页面加载时调用） */
  subscribeGlobalTags(): Promise<void>
  
  /** 取消订阅（页面卸载时调用） */
  unsubscribe(): void
  
  /** 切换筛选标签（本地状态，不持久化） */
  toggleFilter(tagId: string, logic: 'and' | 'or' | 'not'): void
  
  /** 清除所有筛选 */
  clearFilters(): void
  
  /** 使用蓝图（转发给主窗口），使用成功后根据配置自动隐藏窗口 */
  useBlueprint(blueprintPath: string): Promise<void>
  
  /** 记录蓝图使用（更新最近使用列表） */
  recordRecentUse(blueprintPath: string): void
  
  /** 获取最近使用的蓝图列表（computed） */
  get recentBlueprints(): Array<{ path: string; name: string; timestamp: number }>
  
  /** 获取筛选后的蓝图列表（computed） */
  get filteredBlueprints(): Array<{ path: string; name: string; tagIds: string[] }>

## 📊 第四部分：数据流与状态机

### 数据流向

```
主窗口GlobalTags变更流：
  [主窗口用户操作] 
    --(创建/删除/修改标签)--> 
  [GlobalTagsStore.saveGlobalTags()] 
    --(GlobalTagsConfig)--> 
  [QuickAccessIpcHandler监听变更] 
    --(通过'global-tags:updated'频道)--> 
  [快速访问窗口Preload层] 
    --(触发onGlobalTagsUpdated回调)--> 
  [QuickAccessStore更新本地状态] 
    --(响应式更新)--> 
  [QuickAccessPage自动重新渲染]

快速访问窗口蓝图使用流：
  [用户点击蓝图图标] 
    --(blueprintPath)--> 
  [QuickAccessStore.useBlueprint()] 
    --(通过IPC 'quick-access:use-blueprint')--> 
  [主进程转发] 
    --(通过'blueprint:use'频道)--> 
  [主窗口BlueprintHandler] 
    --(调用Python自动化服务)--> 
  [游戏内使用蓝图]
    --(使用成功)--> 
  [QuickAccessStore.recordRecentUse()] 
    --(更新最近使用列表)--> 
  [根据配置判断是否自动隐藏] 
    --(autoHideAfterUse=true)--> 
  [QuickAccessWindowService.hide()]

快捷键唤出流：
  [用户按下Ctrl+Shift+Q] 
    --(globalShortcut事件)--> 
  [QuickAccessShortcutService] 
    --(调用toggle())--> 
  [QuickAccessWindowService] 
    --(判断isVisible)--> 
  [show()或hide()]
```

### 快速访问窗口状态机

```
窗口生命周期状态机：
  UNINITIALIZED（未初始化）
    -> [应用启动，读取配置] -> CREATED（已创建但隐藏）
  
  CREATED（已创建但隐藏）
    -> [快捷键/托盘菜单触发] -> VISIBLE（可见）
    -> [应用退出] -> DESTROYED（已销毁）
  
  VISIBLE（可见）
    -> [用户点击关闭/Esc键/快捷键] -> CREATED（已创建但隐藏）
    -> [蓝图使用成功且autoHideAfterUse=true] -> CREATED（已创建但隐藏）
    -> [失去焦点且autoHide=true] -> CREATED（已创建但隐藏）
    -> [应用退出] -> DESTROYED（已销毁）
  
  DESTROYED（终态）
    -> 不可恢复

订阅状态机：
  UNSUBSCRIBED（未订阅）
    -> [页面加载，调用subscribeGlobalTags()] -> SUBSCRIBING（订阅中）
  
  SUBSCRIBING（订阅中）
    -> [主窗口返回初始数据] -> SUBSCRIBED（已订阅）
    -> [超时3s无响应] -> FAILED（订阅失败）
  
  SUBSCRIBED（已订阅）
    -> [收到'global-tags:updated'事件] -> SUBSCRIBED（更新本地状态）
    -> [页面卸载/窗口关闭] -> UNSUBSCRIBED（未订阅）
  
  FAILED（订阅失败）
    -> [用户点击重试] -> SUBSCRIBING（订阅中）
    -> [页面卸载] -> UNSUBSCRIBED（未订阅）
```

## ⚠️ 第五部分：关键决策点与实施注意事项

### 决策点 1：窗口是隐藏还是销毁？

**选择**：首次唤出时创建，关闭时隐藏（hide）而不销毁（destroy）

**理由**：
- 快速响应：再次唤出时<100ms（隐藏）vs <500ms（重新创建）
- 状态保持：保留用户的筛选条件和滚动位置
- 内存成本可接受：隐藏窗口仅占用约30MB

**实施要点**：
- 应用启动时预创建窗口但不显示（减少首次唤出延迟）
- 监听窗口的'close'事件，阻止默认行为，改为hide()
- 应用退出时统一destroy所有窗口
- 提供手动清理内存的方式（设置中的"重启快速访问窗口"按钮）

**反模式**：
- ❌ 不要每次唤出都创建新窗口（性能差）
- ❌ 不要在hide状态下继续执行高频操作（浪费资源）

---

### 决策点 2：数据同步使用SharedWorker还是IPC？

**选择**：使用Electron IPC的发布-订阅模式

**理由**：
- Electron IPC性能足够（<10ms延迟）
- SharedWorker在Electron中支持有限且复杂
- IPC可以精确控制同步时机（避免过度更新）
- 主进程可以作为数据同步的中心节点

**实施要点**：
- 主窗口GlobalTagsStore.saveGlobalTags()后，通过IPC主动推送给快速访问窗口
- 使用debounce（300ms）避免短时间内多次推送
- 快速访问窗口使用版本号（lastSyncTime）检测数据新鲜度
- 主窗口未就绪时，快速访问窗口降级为"仅展示，不可筛选"模式

**反模式**：
- ❌ 不要让快速访问窗口轮询主窗口（浪费资源）
- ❌ 不要让快速访问窗口直接读写配置文件（数据不一致风险）

---

### 决策点 3：快捷键冲突如何处理？

**选择**：注册时检测冲突，冲突时提示用户修改并fallback到默认快捷键

**理由**：
- 用户体验优先：明确告知冲突原因
- 避免静默失败：快捷键无效时用户无感知
- 提供降级方案：托盘菜单始终可用

**实施要点**：
- 使用electron.globalShortcut.register()的返回值判断是否注册成功
- 注册失败时，尝试注册备用快捷键（Ctrl+Alt+Q）
- 备用快捷键也失败时，弹出通知提示用户修改
- 在设置页面提供"测试快捷键"按钮，实时检测冲突
- 快捷键配置格式统一为'Ctrl+Shift+Q'，内部转换为Electron Accelerator格式

**反模式**：
- ❌ 不要使用系统保留的快捷键（如Ctrl+C、Ctrl+V）
- ❌ 不要在前台应用有焦点时拦截所有按键（用户体验差）

---

### 决策点 4：快速访问窗口是否支持多实例？

**选择**：不支持，全局单例

**理由**：
- 业务场景单一：用户只需要一个快速访问窗口
- 避免资源浪费：多实例会占用多倍内存
- 简化状态管理：单例模式下数据同步逻辑简单

**实施要点**：
- QuickAccessWindowService使用单例模式
- 重复触发快捷键时toggle现有窗口，而不是创建新窗口
- 提供isVisible()方法供外部查询窗口状态

**反模式**：
- ❌ 不要为每个配置创建独立的快速访问窗口
- ❌ 不要在主窗口关闭时销毁快速访问窗口（应该同时退出应用）

---

### 决策点 5：标签筛选逻辑是在前端还是后端？

**选择**：在快速访问窗口的前端（QuickAccessStore）

**理由**：
- 数据量小：标签和蓝图数量通常<1000，前端计算无性能问题
- 实时响应：前端计算无需IPC往返，<16ms完成
- 复用现有逻辑：主窗口已有filterBlueprintsByTags工具函数

**实施要点**：
- 复用Frontend/GUI/pages/.../utils/tagHelpers.ts中的filterBlueprintsByTags()
- 将工具函数提升为通用工具（移至Frontend/GUI/utils/或保持路径不变通过别名导入）
- 快速访问窗口通过相对路径或别名导入
- 筛选逻辑使用Vue computed，自动响应activeFilters变化

**反模式**：
- ❌ 不要在主进程中实现筛选逻辑（增加IPC通信次数）
- ❌ 不要在每次筛选时重新遍历所有蓝图（使用索引优化）

### 决策点 6：窗口置顶（Always on Top）的默认值？

**选择**：默认开启（alwaysOnTop: true）

**理由**：
- 核心使用场景：游戏全屏时需要窗口覆盖在游戏上方
- 用户预期：快速访问窗口应该"浮"在游戏窗口上
- 可配置：用户可以在设置中关闭

**实施要点**：
- 创建窗口时设置alwaysOnTop: true
- 在窗口底部提供快捷切换按钮（图钉图标）
- 切换时调用window.setAlwaysOnTop()
- 状态变化时保存到GeneralSettings

**反模式**：
- ❌ 不要在用户未明确关闭置顶时自动取消置顶
- ❌ 不要在所有场景下都置顶（用户明确关闭时应尊重）

## 🔍 第八部分：风险与缓解措施

### 风险1：全局快捷键在游戏全屏时不响应

**概率**：中

**影响**：用户无法在游戏中唤出窗口，核心功能不可用

**缓解措施**：
1. 优先使用Electron的globalShortcut API（支持大部分游戏）
2. 如果游戏独占输入，提示用户使用Alt+Tab切换到桌面后再按快捷键
3. 提供"游戏模式"选项：自动检测游戏启动，创建游戏内覆盖窗口（后期扩展）

### 风险2：IPC通信延迟导致数据不同步

**概率**：低

**影响**：用户看到过期的标签或蓝图列表

**缓解措施**：
1. 使用时间戳（lastSyncTime）检测数据新鲜度
2. 快速访问窗口显示"数据更新于X秒前"提示
3. 提供手动刷新按钮
4. 主窗口推送时附带版本号，快速访问窗口拒绝旧版本数据

### 风险3：内存泄漏（窗口隐藏但未释放资源）

**概率**：中

**影响**：长时间运行后内存占用持续增长

**缓解措施**：
1. 窗口隐藏时清理不必要的定时器和监听器
2. 使用WeakMap存储蓝图图标缓存（自动GC）
3. 提供"重启快速访问窗口"按钮（手动清理）
4. 监控内存占用，超过100MB时自动destroy并重新创建

### 风险4：快捷键录制时误触发其他操作

**概率**：高

**影响**：用户录制快捷键时意外触发系统操作

**缓解措施**：
1. 录制时阻止事件冒泡（event.preventDefault()）
2. 录制UI使用模态对话框，明确提示"请按下快捷键"
3. 过滤无效组合（如单独的Shift、Ctrl）
4. 提供"取消录制"按钮

## 总结

本设计方案完整定义了快速访问窗口的架构、接口、数据流和实施细节。核心特性：

1. **性能优先**：预创建+隐藏模式，<100ms唤出速度
2. **数据一致性**：IPC订阅模式，<100ms同步延迟
3. **用户体验**：全局快捷键+托盘菜单+置顶窗口，游戏友好
4. **智能交互**：使用蓝图后自动隐藏（可配置），快速回到游戏
5. **最近使用**：记录最近10个使用的蓝图，顶部置顶显示，快速访问常用蓝图
6. **可配置性**：快捷键、窗口尺寸、置顶行为、自动隐藏、最近使用数量均可自定义
7. **架构清晰**：订阅者模式+代理窗口模式，职责分离
8. **组件复用**：复用General.Titlebar组件，保持UI一致性

实施者可以按照文件清单的阶段顺序，从类型定义到后端服务再到前端页面，逐步实现所有功能。所有关键决策点已明确，避免实施过程中的架构偏差。
