## 📊 当前标签系统架构分析

### 1️⃣ **标签的两种类型**

#### 用户标签（User Tags）
- **存储位置**：配置文件的 `tags` 数组
- **ID格式**：`tag-{timestamp}-{random}`
- **字段**：`id`, `name`, `color`
- **特点**：用户手动创建和管理

#### 路径标签（Path Tags）
- **存储位置**：不存储，动态计算
- **ID格式**：`path:{directory路径}`
- **来源**：从蓝图的 `directoryPath` 字段自动生成
- **级数控制**：通过 `pathTagLevels` 配置（1-6级）

### 2️⃣ **当前的耦合关系**

```
┌─────────────────────────────────────────────────────────┐
│              ConfigFileData (配置文件)                    │
├─────────────────────────────────────────────────────────┤
│ • id, name, version                                     │
│ • tags: TagDefinition[]  ← 标签定义（与配置绑定）        │
│ • pathTagLevels: number  ← 路径标签级数                  │
│ • tree: ActiveBlueprintNode[]                           │
│   └─ blueprint节点                                       │
│      └─ tags: string[]  ← 标签ID引用（只含用户标签）     │
│      └─ directoryPath   ← 路径标签基础（动态计算）       │
└─────────────────────────────────────────────────────────┘
```

**核心问题：**
- ❌ 标签定义绑定在配置文件中，切换配置 = 切换标签库
- ❌ 蓝图的标签引用基于配置内的节点ID，无法跨配置复用
- ❌ 每个配置都有独立的标签体系，无法统一管理

### 4️⃣ **解耦重构方案**

> **🔄 重构策略：** 本次采用**全新架构重构**，不考虑向后兼容性。旧的配置数据将被清除，采用全新的存储结构。但必须确保与现有系统模块（蓝图源管理、自动化配置等）的接口保持兼容。

#### 方案A：全局标签系统（✅ 采用方案）

**架构设计：**

```
┌──────────────────────────────────────────────────────┐
│          GlobalTagsConfig (全局标签配置)              │
├──────────────────────────────────────────────────────┤
│ tags: TagDefinition[]                                │
│ blueprintTags: Map<blueprintPath, tagIds[]>          │
│   ↓                                                  │
│   以蓝图路径为key，而非配置内的节点ID                 │
└──────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────┐
│      ActiveBlueprintConfig (激活配置 - 简化)          │
├──────────────────────────────────────────────────────┤
│ pathTagLevels: number                                │
│ tree: ActiveBlueprintNode[]                          │
│   └─ 不再存储tags字段                                │
│   └─ 标签关系通过blueprintPath查询全局配置            │
└──────────────────────────────────────────────────────┘
```

**实施说明：**
- 🆕 全新的配置文件结构，存储于 `global-tags.json`
- 🗑️ 旧的嵌入式标签配置将被废弃
- 🔌 确保与其他模块的 API 接口保持稳定（如 `store.batchAddTags()` 等方法签名不变）
- 🎯 标签关系基于蓝图文件路径，实现跨配置复用

**优点：**
- ✅ 标签定义全局统一，不随配置切换
- ✅ 蓝图-标签关系基于路径，可跨配置复用
- ✅ 便于全局标签管理和统计
- ✅ 架构更清晰，职责分离

**注意事项：**
- ⚠️ 需要新的存储文件 `global-tags.json`
- ⚠️ 用户需要重新配置标签（旧数据不保留）
- ⚠️ 增加了一个新的数据源层（GlobalTagsStore）

#### 方案B：混合方案（❌ 本次不采用）

```
保留配置内的标签定义，但新增全局标签关系映射
- 短期：兼容现有配置，标签仍存储在配置中
- 中期：同步标签定义到全局配置
- 长期：迁移为全局标签系统
```

**不采用原因：** 既然是全面重构，混合方案的渐进式迁移策略不适用。

### 6️⃣ **路径标签处理建议**

路径标签的特殊性：
- 它们是**动态计算的**，不需要持久化
- `pathTagLevels` 配置可以保留在各个配置中（因为不同配置可能需要不同的路径追踪级数）
- 路径标签树的构建逻辑无需改动

**建议：** 路径标签继续保持动态计算，只解耦用户标签系统

## 🔌 模块对接关键代码

### 1️⃣ **全局标签Store接口（保持向后兼容）**

```typescript
// stores/GlobalTags/index.ts
export const useGlobalTagsStore = defineStore('globalTags', {
  state: () => ({
    tags: [] as TagDefinition[],
    blueprintTagsMap: new Map<string, string[]>(), // key: blueprintPath
  }),
  
  actions: {
    // ✅ 对外暴露的核心方法（兼容原 ActiveBlueprintStore 的接口）
    
    /**
     * 批量添加标签（兼容接口）
     * @param blueprintPaths 蓝图路径数组（而非节点ID）
     * @param tagId 标签ID
     */
    async batchAddTags(blueprintPaths: string[], tagId: string): Promise<void> {
      for (const path of blueprintPaths) {
        const tags = this.blueprintTagsMap.get(path) || []
        if (!tags.includes(tagId)) {
          tags.push(tagId)
          this.blueprintTagsMap.set(path, tags)
        }
      }
      await this.saveGlobalTags()
    },
    
    /**
     * 批量移除标签（兼容接口）
     */
    async batchRemoveTags(blueprintPaths: string[], tagId: string): Promise<void> {
      for (const path of blueprintPaths) {
        const tags = this.blueprintTagsMap.get(path)
        if (tags) {
          const index = tags.indexOf(tagId)
          if (index !== -1) {
            tags.splice(index, 1)
          }
        }
      }
      await this.saveGlobalTags()
    },
    
    /**
     * 创建标签（兼容接口）
     */
    async createTag(name: string, color: string): Promise<void> {
      const tagId = `tag-${Date.now()}-${Math.random().toString(36).substring(2, 9)}`
      this.tags.push({ id: tagId, name, color })
      await this.saveGlobalTags()
    },
    
    /**
     * 删除标签（兼容接口）
     */
    async deleteTag(tagId: string): Promise<void> {
      const index = this.tags.findIndex(t => t.id === tagId)
      if (index !== -1) {
        this.tags.splice(index, 1)
      }
      // 从所有蓝图中移除该标签
      for (const [path, tags] of this.blueprintTagsMap.entries()) {
        const tagIndex = tags.indexOf(tagId)
        if (tagIndex !== -1) {
          tags.splice(tagIndex, 1)
        }
      }
      await this.saveGlobalTags()
    },
    
    /**
     * 获取蓝图的标签ID列表
     */
    getBlueprintTags(blueprintPath: string): string[] {
      return this.blueprintTagsMap.get(blueprintPath) || []
    },
  }
})
```

### 2️⃣ **ActiveBlueprintStore 适配层（委托模式）**

```typescript
// stores/ActiveBlueprint/index.ts
import { useGlobalTagsStore } from '../GlobalTags'

export const useActiveBlueprintStore = defineStore('activeBlueprint', {
  actions: {
    // ✅ 委托给全局标签Store（保持接口签名不变）
    
    /**
     * 批量添加标签（适配器方法）
     * @param nodeIds 节点ID数组（内部转换为 blueprintPath）
     * @param tagId 标签ID
     */
    async batchAddTags(nodeIds: string[], tagId: string): Promise<void> {
      const globalTagsStore = useGlobalTagsStore()
      
      // 🔑 关键：将节点ID转换为蓝图路径
      const blueprintPaths: string[] = []
      for (const nodeId of nodeIds) {
        const node = this.findNodeById(nodeId)
        if (node?.type === 'blueprint' && node.path) {
          blueprintPaths.push(node.path)
        }
      }
      
      // 委托给全局Store
      await globalTagsStore.batchAddTags(blueprintPaths, tagId)
    },
    
    /**
     * 批量移除标签（适配器方法）
     */
    async batchRemoveTags(nodeIds: string[], tagId: string): Promise<void> {
      const globalTagsStore = useGlobalTagsStore()
      
      const blueprintPaths: string[] = []
      for (const nodeId of nodeIds) {
        const node = this.findNodeById(nodeId)
        if (node?.type === 'blueprint' && node.path) {
          blueprintPaths.push(node.path)
        }
      }
      
      await globalTagsStore.batchRemoveTags(blueprintPaths, tagId)
    },
    
    /**
     * 创建标签（直接委托）
     */
    async createTag(name: string, color: string): Promise<void> {
      const globalTagsStore = useGlobalTagsStore()
      await globalTagsStore.createTag(name, color)
    },
    
    /**
     * 删除标签（直接委托）
     */
    async deleteTag(tagId: string): Promise<void> {
      const globalTagsStore = useGlobalTagsStore()
      await globalTagsStore.deleteTag(tagId)
    },
  }
})
```

### 4️⃣ **Electron IPC 通信（Backend）**

```typescript
// Backend/Electron/ipc/globalTags.ts
import { ipcMain } from 'electron'
import * as fs from 'fs/promises'
import * as path from 'path'
import { app } from 'electron'

const GLOBAL_TAGS_FILE = path.join(app.getPath('userData'), 'global-tags.json')

export function registerGlobalTagsHandlers() {
  // ✅ 加载全局标签
  ipcMain.handle('global-tags:load', async () => {
    try {
      const data = await fs.readFile(GLOBAL_TAGS_FILE, 'utf-8')
      return JSON.parse(data)
    } catch (error) {
      // 文件不存在时返回空配置
      return {
        version: '1.0.0',
        tags: [],
        blueprintTags: {}
      }
    }
  })
  
  // ✅ 保存全局标签
  ipcMain.handle('global-tags:save', async (_, data) => {
    await fs.writeFile(GLOBAL_TAGS_FILE, JSON.stringify(data, null, 2))
    return { success: true }
  })
}

// Backend/Electron/preload.ts
contextBridge.exposeInMainWorld('globalTagsAPI', {
  loadGlobalTags: () => ipcRenderer.invoke('global-tags:load'),
  saveGlobalTags: (data: any) => ipcRenderer.invoke('global-tags:save', data),
})
```
