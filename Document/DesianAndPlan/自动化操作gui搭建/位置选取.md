
# 坐标标定功能技术设计方案

## 📋 第一部分：设计概览

**【目标】**：实现点击式坐标标定，点击定位按钮后隐藏主窗口、全屏显示截图叠加层、用户点击标定坐标、自动填充配置表单

**【范围】**：
- 在范围内：创建截图叠加窗口、鼠标点击坐标捕获、多显示器支持、坐标自动填充、窗口显隐控制
- 不在范围内：智能坐标识别、历史坐标管理、坐标验证（留给后期优化）

**【技术栈决策】**：
- 截图捕获：Electron `desktopCapturer` API（原因：跨平台、原生支持多显示器）
- 叠加窗口：Electron `BrowserWindow` + `frame: false, transparent: true`（原因：全屏覆盖、支持鼠标事件）
- 显示器检测：Electron `screen` 模块（原因：精确获取显示器边界和缩放比例）
- 前后端通信：IPC `invoke/handle` + `send/on` 混合模式（原因：标定需要单向事件推送）

**【架构模式】**：责任链模式（主窗口 → IPC → Service → 叠加窗口 → IPC → 前端表单）

**【核心约束】**：
- 截图延迟：< 500ms（从点击到显示叠加窗口）
- 坐标精度：1px（需处理 DPI 缩放）
- 多显示器：支持最多 4 个显示器
- 内存占用：< 50MB（单个截图窗口，1080p 显示器）
- 兼容性：Windows 10+, macOS 10.15+

## 🏗️ 第二部分：模块划分与职责

```
坐标标定系统
├─ 前端触发层（ManualConfigForm.vue）
│   ├─ 职责：触发标定流程、接收标定结果、更新表单
│   ├─ 输入：用户点击事件（'inputField' | 'firstBlueprint'）
│   ├─ 输出：{ x: number, y: number, displayIndex: number }
│   └─ 关键逻辑：
│       1. 调用 window.electron.automationConfig.startCalibration(type)
│       2. 监听 'calibration:result' 事件
│       3. 解构 { x, y, displayIndex } 填充 localParams
│       4. 触发 handleBlur() 保存配置
│
├─ IPC 通信层（AutomationConfigHandler.ts）
│   ├─ 职责：转发标定请求到 Service、推送标定结果到渲染进程
│   ├─ 输入：IpcMainInvokeEvent + calibrationType: string
│   ├─ 输出：Promise<void>（立即返回，结果通过事件推送）
│   └─ 关键逻辑：
│       1. 接收 'automation-config:start-calibration' invoke
│       2. 调用 CalibrationService.startCalibration(mainWindow, type)
│       3. Service 完成后通过 event.sender.send() 推送结果
│       4. 监听 'automation-config:cancel-calibration' 处理取消
│
├─ 坐标标定服务（CalibrationService）
│   ├─ 职责：管理叠加窗口生命周期、捕获屏幕截图、处理点击事件
│   ├─ 输入：mainWindow: BrowserWindow, calibrationType: string
│   ├─ 输出：CalibrationResult { x, y, displayIndex, timestamp }（物理坐标）
│   ├─ 依赖：Electron screen 模块、desktopCapturer API
│   └─ 关键逻辑：
│       1. 调用 captureAllScreens() 获取所有显示器截图（返回 Map<displayId, dataURL>）
│       2. 隐藏 mainWindow（mainWindow.hide()）
│       3. 为每个显示器创建叠加窗口（createOverlayWindow(display, screenshotDataURL)）
│       4. 叠加窗口监听 'calibration:click' IPC 事件
│       5. 接收点击坐标后：
│          - 计算逻辑坐标（clickX + display.bounds.x, clickY + display.bounds.y）
│          - 转换为物理坐标（logicalCoord * display.scaleFactor）
│          - 确定 displayIndex（根据 display.id）
│       6. 销毁所有叠加窗口、显示 mainWindow
│       7. 返回 CalibrationResult（包含物理坐标）
│   └─ 错误处理：
│       - 截图失败：降级到纯色背景 + 提示文字
│       - 用户按 ESC：取消标定，恢复主窗口
│       - 窗口创建失败：抛出异常，终止流程
│
├─ 截图捕获模块（ScreenCaptureUtil）
│   ├─ 职责：批量捕获所有显示器截图
│   ├─ 输入：void
│   ├─ 输出：Promise<Map<string, string>>（displayId → base64 dataURL）
│   └─ 关键逻辑：
│       1. 调用 screen.getAllDisplays() 获取显示器列表
│       2. 调用 desktopCapturer.getSources({ types: ['screen'], thumbnailSize: { width, height } })
│       3. 遍历 sources，匹配 source.display_id 与 display.id
│       4. 转换 NativeImage 为 dataURL（source.thumbnail.toDataURL()）
│       5. 返回 Map<displayId, dataURL>
│   └─ 反模式：
│       ❌ 不要使用 win.capturePage()（仅限窗口内容，不包含全屏）
│       ❌ 不要同步获取截图（会阻塞主进程）
│
├─ 叠加窗口管理器（OverlayWindowManager）
│   ├─ 职责：创建透明叠加窗口、加载截图、监听点击
│   ├─ 输入：display: Display, screenshotDataURL: string
│   ├─ 输出：BrowserWindow
│   └─ 关键逻辑：
│       窗口配置：
│       {
│         x: display.bounds.x,
│         y: display.bounds.y,
│         width: display.bounds.width,
│         height: display.bounds.height,
│         frame: false,
│         transparent: true,
│         alwaysOnTop: true,
│         fullscreen: true,
│         skipTaskbar: true,
│         resizable: false,
│         movable: false,
│         webPreferences: {
│           nodeIntegration: false,
│           contextIsolation: true,
│           preload: path.join(__dirname, 'preload-overlay.js')
│         }
│       }
│       
│       加载内容：
│       - 方案 A：loadURL(data:text/html, 内联 HTML + 截图 base64)
│       - 方案 B（推荐）：loadFile('overlay.html')，通过 IPC 传递截图
│       
│       事件监听：
│       - 监听渲染进程发送的 'calibration:click' 事件
│       - 监听键盘 ESC 键取消（通过 webContents.send）
│   └─ 反模式：
│       ❌ 不要用 setIgnoreMouseEvents(true)（会导致点击无法捕获）
│       ❌ 不要在主窗口 preload 中处理叠加窗口逻辑（隔离不同窗口的 IPC）
│
└─ 叠加窗口渲染层（overlay.html + overlay.ts）
    ├─ 职责：显示截图、绘制十字准星、发送点击坐标
    ├─ 输入：screenshotDataURL: string（通过 IPC 接收）
    ├─ 输出：{ x: number, y: number }（窗口相对坐标）
    └─ 关键逻辑：
        HTML 结构：
        <div id="overlay">
          <img id="screenshot" />
          <div id="crosshair"></div>  // 跟随鼠标的十字准星
          <div id="hint">点击屏幕标定坐标，按 ESC 取消</div>
        </div>
        
        交互逻辑：
        1. 监听 'set-screenshot' IPC 事件设置 img.src
        2. 监听 mousemove 更新十字准星位置（CSS transform: translate）
        3. 监听 click 事件：
           - 获取 event.clientX, event.clientY
           - 发送 'calibration:click' IPC 事件到主进程
        4. 监听 keydown ESC 发送 'calibration:cancel'
        
        样式要点：
        - cursor: crosshair
        - 十字准星：2px 红色线，长度 40px，中心空白 10px
        - 半透明暗色蒙层（rgba(0,0,0,0.3)）突出截图
```

```typescript
// ===== public/types/automation-config/calibration.ts =====

 * 坐标标定结果

 * @注意事项 坐标为当前环境定制，环境变化（DPI/显示器布局）需重新标定
 */
export interface CalibrationResult {
  x: number                 // 物理 X 坐标（设备像素）
  y: number                 // 物理 Y 坐标（设备像素）

export class CalibrationService {
  private static instance: CalibrationService
  private isCalibrating: boolean
  private overlayWindows: BrowserWindow[]
  private calibrationResolve: ((result: CalibrationResult) => void) | null

   * 获取单例实例

  static getInstance(): CalibrationService
```

## 📊 第四部分：数据流与状态机

**数据流向：**
```
[用户点击定位按钮]
  --(calibrationType: 'inputField')--> 
[ManualConfigForm.vue]
  --(IPC invoke: 'automation-config:start-calibration')--> 
[AutomationConfigHandler.ts]
  --(调用方法)--> 
[CalibrationService.startCalibration()]
  --(调用)--> 
[ScreenCaptureUtil.captureAllScreens()]
  --(返回 Map<displayId, dataURL>)--> 
[CalibrationService]
  --(创建多个)--> 
[叠加窗口 BrowserWindow × N]
  --(用户点击)--> 
[overlay.ts: click 事件]
  --(IPC send: 'calibration:click' + 坐标)--> 
[CalibrationService.handleOverlayClick()]
  --(计算绝对坐标 + DPI 处理)--> 
[CalibrationResult 对象]
  --(IPC send: 'calibration:result')--> 
[ManualConfigForm.vue: onCalibrationResult 回调]
  --(更新 localParams)--> 
[表单自动填充]
```

**标定流程状态机：**
```
IDLE（空闲）
  -> [用户点击定位按钮] -> CAPTURING（截图中）
  
CAPTURING（截图中）
  -> [截图成功] -> OVERLAYING（叠加窗口显示）
  -> [截图失败] -> ERROR_CAPTURE（截图错误）
  
OVERLAYING（叠加窗口显示）
  -> [用户点击屏幕] -> PROCESSING（处理坐标）
  -> [用户按 ESC] -> CANCELLED（已取消）
  
PROCESSING（处理坐标）
  -> [坐标计算完成] -> COMPLETED（已完成）
  -> [计算异常] -> ERROR_PROCESSING（处理错误）
  
ERROR_CAPTURE/ERROR_PROCESSING（错误态）
  -> [恢复主窗口] -> IDLE
  
COMPLETED/CANCELLED（终态）
  -> [清理资源] -> IDLE
```

## ⚠️ 第五部分：关键决策点与实施注意事项

**决策点 1：截图方案选择**
- 选择：`desktopCapturer.getSources({ types: ['screen'] })`
- 理由：跨平台、支持多显示器、可获取完整屏幕内容（包括其他应用窗口）
- 实施要点：
  - `thumbnailSize` 必须设置为显示器的物理分辨率（`display.bounds.width/height * scaleFactor`）
  - 匹配 `source.display_id` 与 `display.id`（使用字符串比较，注意类型转换）
  - 截图为 `NativeImage`，需调用 `.toDataURL()` 转换为 base64
  - 超时控制：5 秒内未完成截图则降级到纯色背景
- 反模式：
  - ❌ 不要用 `webContents.capturePage()`（仅捕获窗口内容）
  - ❌ 不要用第三方库如 `screenshot-desktop`（增加依赖、不稳定）

**决策点 2：叠加窗口的 HTML 加载方式**
- 选择：`loadFile('overlay.html')` + IPC 传递截图数据
- 理由：避免 data URI 长度限制（base64 截图可达数 MB）、便于调试
- 实施要点：
  - 创建 `src-electron/windows/overlay.html`（独立文件）
  - 窗口创建后立即发送 `'set-screenshot'` IPC 事件传递 dataURL
  - overlay.ts 中监听该事件并设置 `<img>` 的 `src`
  - preload 文件：`src-electron/Preload/overlay.ts`（独立于主窗口 preload）
- 反模式：
  - ❌ 不要用 `loadURL('data:text/html,<html>...')`（长字符串难维护、性能差）
  - ❌ 不要在主窗口加载叠加层（会干扰主应用状态）

**决策点 3：坐标计算与存储**
- 选择：直接计算并存储物理坐标（设备像素）
- 理由：@nut-tree/nut-js 使用物理坐标系统，用户标定即为当前环境定制，简单直接
- 实施要点：
  - 获取点击的窗口所属的 `display` 对象（通过 `display.id` 匹配）
  - 坐标计算三步骤：
    ```typescript
    // 步骤 1：计算逻辑坐标（CSS 像素，相对于主显示器左上角）
    const logicalX = clickX + display.bounds.x
    const logicalY = clickY + display.bounds.y
    
    // 步骤 2：转换为物理坐标（设备像素，用于 nut-js）
    const physicalX = Math.round(logicalX * display.scaleFactor)
    const physicalY = Math.round(logicalY * display.scaleFactor)
    
    // 步骤 3：存储物理坐标
    return { x: physicalX, y: physicalY, displayIndex, timestamp }
    ```
  - 执行自动化时直接使用：
    ```typescript
    await mouse.setPosition({ x: config.x, y: config.y })  // 无需转换
    ```
  - displayIndex 从 0 开始，按 `screen.getAllDisplays()` 返回顺序
- 反模式：
  - ❌ 不要存储逻辑坐标然后执行时转换（增加复杂度）
  - ❌ 不要在存储前再次乘以 scaleFactor（已经转换过了）
  - ❌ 不要直接使用 `event.screenX/screenY`（Electron BrowserWindow 中不准确）
  - ❌ 不要做复杂的环境检测（环境变了就重新标定）

**决策点 4：主窗口隐藏时机**
- 选择：截图完成后、创建叠加窗口前隐藏
- 理由：避免主窗口出现在截图中、减少用户视觉干扰
- 实施要点：
  - 调用 `mainWindow.hide()` 而非 `mainWindow.minimize()`（minimize 仍占用任务栏）
  - 添加 200ms 延迟后再创建叠加窗口（确保主窗口完全隐藏）
  - 标定完成或取消后调用 `mainWindow.show()` 恢复
  - 使用 `mainWindow.restore()` + `mainWindow.focus()` 确保窗口回到前台
- 反模式：
  - ❌ 不要在截图前隐藏（会导致截图到桌面背景，用户无法预览当前状态）
  - ❌ 不要用 `mainWindow.setOpacity(0)`（仍会占用位置）

**决策点 5：ESC 取消机制**
- 选择：在叠加窗口的渲染进程监听 `keydown` 事件
- 理由：全屏叠加窗口能捕获所有键盘事件，响应速度快
- 实施要点：
  - overlay.ts 中监听 `document.addEventListener('keydown', e => { if (e.key === 'Escape') ... })`
  - 发送 `'calibration:cancel'` IPC 事件到主进程
  - 主进程调用 `CalibrationService.cancelCalibration()`
  - Promise reject 一个 `UserCancelledError`
  - 前端捕获该错误，静默处理（不显示错误提示）
- 反模式：
  - ❌ 不要在主进程注册全局快捷键（`globalShortcut.register('Escape')`）可能与系统冲突
  - ❌ 不要依赖窗口失焦事件（用户可能点击其他应用）

**决策点 6：错误处理策略**
- 选择：截图失败降级、坐标计算错误回滚
- 理由：提升用户体验，避免流程中断
- 实施要点：
  - 截图失败（5 秒超时）：
    - 生成纯灰色背景（#808080）+ 白色提示文字 "无法获取截图，请点击标定"
    - 仍创建叠加窗口，允许用户凭记忆点击
  - 窗口创建失败：
    - 抛出 `Error('Failed to create overlay window')`
    - 前端显示 toast 提示 "标定失败，请重试"
  - 坐标计算异常：
    - 记录错误日志（console.error）
    - 返回默认值 `{ x: 0, y: 0, displayIndex: 0, ... }`
    - 前端提示 "标定异常，请重新标定"
- 反模式：
  - ❌ 不要静默失败（用户不知道发生了什么）
  - ❌ 不要阻塞主进程（使用 async/await 正确处理异步）

## 🧪 第六部分：验收标准

**功能验收：**
- ✓ 点击"定位"按钮，500ms 内主窗口消失，叠加窗口显示当前屏幕截图
- ✓ 鼠标移动时，红色十字准星跟随鼠标（无延迟）
- ✓ 点击屏幕任意位置，表单的 X/Y 坐标立即填充为点击位置的绝对坐标
- ✓ 在副显示器点击，`displayIndex` 自动填充为该显示器索引（非 0）
- ✓ 按 ESC 键取消标定，主窗口恢复，表单坐标不变
- ✓ 标定完成后，叠加窗口自动关闭，主窗口恢复到前台

**多显示器验收：**
- ✓ 2 个显示器（1920×1080 + 1920×1080 横向排列），点击右侧显示器中心，存储物理坐标
- ✓ 主显示器 150% DPI 缩放，点击后存储的物理坐标可被 nut-js 准确执行
