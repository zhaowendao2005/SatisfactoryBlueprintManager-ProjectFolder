# Blueprint 管理模块技术设计方案

## 📋 第一部分：设计概览

**【目标】**：实现蓝图源管理（BlueprintSource）和激活蓝图管理（ActiveBlueprint）的双树视图系统。
- **BlueprintSource**：展示添加的目录中的蓝图文件树结构（懒加载），支持激活/取消激活操作
- **ActiveBlueprint**：展示已激活的蓝图集合，支持用户自定义分组和拖拽排序
- **激活/取消激活**：激活操作将蓝图添加到 ActiveBlueprint 树，取消激活则从树中完全移除
- **分组管理**：ActiveBlueprint 的分组信息独立于文件系统，当前使用纯状态（Mock），未来存储为 JSON

**【范围】**：
- **在范围内**：
  - BlueprintSource 树形结构展示（目录+蓝图文件，懒加载，复选框，自定义节点）
  - ActiveBlueprint 树形结构展示（可拖拽，分组管理，上下文菜单，自定义节点）
  - BlueprintSource 中的激活/取消激活操作（点击激活按钮 → 蓝图添加到 ActiveBlueprint；点击取消激活 → 蓝图从 ActiveBlueprint 移除）
  - Mock 数据层和 Datasource 适配层（Mock 阶段使用纯状态，未来 ActiveBlueprint 存储为 JSON）
- **不在范围内**：
  - 真实文件系统读取（Mock 阶段）
  - 蓝图内容解析和渲染
  - 图标视图实现（仅声明接口）

**【技术栈决策】**：
- UI 组件：Element Plus Tree（原因：符合需求的懒加载、复选框、拖拽、自定义节点支持）
- 状态管理：Pinia Store（原因：跨组件共享蓝图源和激活蓝图状态）
- 数据适配：Datasource 层（原因：解耦 Mock 和真实数据源，便于后续替换）
- 图标库：Element Plus Icons（原因：统一图标风格）
- 样式：SCSS + Flex 布局（原因：灵活的响应式布局）

**【架构模式】**：
- 分层架构：`Vue 组件 -> Pinia Store -> Datasource -> Mock/Real Data`
- 适配器模式：Datasource 层适配不同数据源（Mock/Electron IPC）

**【核心约束】**：
- 懒加载：目录节点首次展开时才加载子节点（减少初始渲染负担）
- 拖拽限制：仅允许在 ActiveBlueprint 树内拖拽，不允许跨树拖拽
- 节点高度：固定高度 40px（保证视觉一致性）
- 工具箱按钮：最多 3 个（避免节点过宽）
- 滚动容器：使用 CSS `overflow-y: scroll`（而非 auto，保持滚动条可见性）

### 模块树

```

│   ├─ 输出：激活的蓝图列表（同步到 ActiveBlueprint）
```

## 🔌 第三部分：关键接口定义

### types.ts（Blueprint 模块类型定义）

```typescript
/**
 * 蓝图节点类型
 */
export type BlueprintNodeType = 'directory' | 'blueprint'

/**
 * 蓝图节点基础接口
 * @注意事项 id 必须全局唯一，建议使用文件路径作为 id
 */
export interface BlueprintNode {
  id: string                    // 唯一标识（文件路径）
  name: string                  // 显示名称
  type: BlueprintNodeType       // 节点类型
  path: string                  // 完整路径
  isActivated: boolean          // 是否已激活
  metadata?: Record<string, any> // 元数据（仅蓝图节点）
  children?: BlueprintNode[]    // 子节点（仅目录节点，懒加载前为 undefined）
  isLeaf?: boolean              // 是否为叶子节点（用于懒加载判断）
}

/**
 * 激活蓝图树节点类型
 */
export type ActiveNodeType = 'group' | 'blueprint'

/**
 * 激活蓝图树节点
 * @注意事项 
 * - 分组节点的 children 永远是数组（可能为空）
 * - 蓝图节点的 children 为 undefined
 * - 分组信息独立于文件系统，完全由用户创建
 * - blueprintId 用于取消激活时查找节点（无论节点在哪个分组下）
 */
export interface ActiveBlueprintNode {
  id: string                    // 唯一标识
  name: string                  // 显示名称
  type: ActiveNodeType          // 节点类型：'group' | 'blueprint'
  blueprintId?: string          // 关联的原始蓝图 id（仅蓝图节点，用于取消激活时查找）
  path?: string                 // 蓝图路径（仅蓝图节点）
  children?: ActiveBlueprintNode[] // 子节点（仅分组节点）
}

/**
 * ActiveBlueprint 树根结构（JSON 格式）
 * @注意事项 未来会存储为 JSON 文件
 */
export interface ActiveBlueprintTree {
  root: ActiveBlueprintNode     // 根节点（虚拟分组）
  version: string               // 数据版本（用于未来迁移）
}

/**
 * 视图类型
 */
export type ViewType = 'tree' | 'icon'

/**
 * 蓝图源配置
 */
export interface BlueprintSource {
  id: string                    // 源 id
  name: string                  // 源名称
  path: string                  // 源路径
  enabled: boolean              // 是否启用
}
```

### ActiveBlueprintDatasource

```typescript
import type { ActiveBlueprintNode } from '../../types'
import type { DropType } from '../ActiveBlueprint/types'

/**
 * ActiveBlueprint 数据源适配器
 * @注意事项 
 * - Mock 阶段：使用纯状态（内存中的对象）
 * - 未来阶段：存储为 JSON 文件（通过 Electron IPC）
 * - 分组信息完全独立，与文件系统无关
 */
export interface IActiveBlueprintDatasource {
  /**
   * 获取激活蓝图树（包含根节点）
   * @注意事项 Mock 阶段返回内存中的状态，未来从 JSON 文件读取
   */
  getActiveTree(): Promise<ActiveBlueprintNode>

  /**
   * 保存激活蓝图树
   * @param tree 完整树结构
   * @注意事项 Mock 阶段仅更新内存状态，未来保存到 JSON 文件
   */
  saveActiveTree(tree: ActiveBlueprintNode): Promise<void>

  /**
   * 添加激活蓝图到根节点
   * @param blueprintId 原始蓝图 id（用于取消激活时查找）
   * @param name 显示名称
   * @param path 蓝图路径
   * @注意事项 蓝图被激活时调用，添加到根节点下
   */
  addBlueprint(blueprintId: string, name: string, path: string): Promise<void>

  /**
   * 移除激活蓝图
   * @param blueprintId 原始蓝图 id（不是节点 id）
   * @注意事项 无论蓝图在哪个分组下，都能找到并删除
   */
  removeBlueprint(blueprintId: string): Promise<void>

  /**
   * 创建分组
   * @param parentId 父节点 id（null 表示根节点）
   * @param name 分组名称
   */
  createGroup(parentId: string | null, name: string): Promise<string>

  /**
   * 删除分组（子节点自动上移）
   * @param groupId 分组 id
   */
  deleteGroup(groupId: string): Promise<void>

  /**
   * 移动节点（拖拽）
   * @param nodeId 被移动的节点 id
   * @param targetId 目标节点 id
   * @param dropType 放置类型
   */
  moveNode(nodeId: string, targetId: string, dropType: DropType): Promise<void>
}
```

## ⚠️ 第五部分：关键决策点与实施注意事项

### 决策点 1：如何实现懒加载？

**选择**：使用 Element Plus Tree 的 `lazy` + `load` 属性

**理由**：Element Plus 原生支持懒加载，避免自行实现展开逻辑

**实施要点**：
- 在 `<el-tree>` 上设置 `:lazy="true"` 和 `:load="loadNode"`
- `loadNode` 函数签名：`(node, resolve) => { ... resolve(data) }`
- 目录节点的 `isLeaf` 属性设为 `false`，蓝图节点设为 `true`
- Store 中的 `loadChildren(nodeId)` 调用 Datasource，返回 Promise
- `load` 函数内调用 `store.loadChildren(node.data.id).then(resolve)`

**反模式**：
- ❌ 不要一次性加载整棵树（浪费内存和渲染时间）
- ❌ 不要在 `load` 函数中直接写业务逻辑，应委托给 Store

---

### 决策点 2：如何实现拖拽排序？

**选择**：使用 Element Plus Tree 的 `draggable` + `allow-drop` + `node-drop` 事件

**理由**：Element Plus 原生支持拖拽，且提供细粒度控制钩子

**实施要点**：
- 在 `<el-tree>` 上设置 `:draggable="true"`
- 使用 `allow-drop` 函数限制拖拽规则：
  ```javascript
  (draggingNode, dropNode, type) => {
    // 禁止拖拽到 Blueprint 节点内部
    if (dropNode.data.type === 'blueprint' && type === 'inner') return false
    // 允许其他情况
    return true
  }
  ```
- 监听 `@node-drop` 事件，调用 `store.moveNode(draggingNode.data.id, dropNode.data.id, type)`
- Store 中的 `moveNode` 调用 Datasource 更新树结构，再保存到 LocalStorage

**反模式**：
- ❌ 不要直接修改 DOM（Element Plus 会自动处理）
- ❌ 不要在拖拽过程中直接保存（应在 drop 事件后统一保存）

---

### 决策点 3：如何实现删除分组时子节点上移？

**选择**：在 Datasource 层实现树结构重组算法

**理由**：树结构操作属于数据层逻辑，不应在 UI 层处理

**实施要点**：
- `deleteGroup(groupId)` 算法：
  ```
  1. 在树中查找 groupId 节点（深度优先搜索）
  2. 记录该节点的 parent 和 children
  3. 将 children 追加到 parent.children（在原位置）
  4. 从 parent.children 中删除 groupId 节点
  5. 保存更新后的树
  ```
- 使用递归函数实现：
  ```javascript
  function findAndDelete(node, groupId) {
    if (!node.children) return false
    const index = node.children.findIndex(child => child.id === groupId)
    if (index !== -1) {
      const deleted = node.children[index]
      const children = deleted.children || []
      node.children.splice(index, 1, ...children) // 替换为子节点
      return true
    }
    return node.children.some(child => findAndDelete(child, groupId))
  }
  ```

**反模式**：
- ❌ 不要直接删除节点而不处理子节点（会导致数据丢失）
- ❌ 不要在 Store 中实现算法（应委托给 Datasource）

---

### 决策点 4：如何实现右键菜单？

**选择**：使用 Element Plus Dropdown + `@node-contextmenu` 事件

**理由**：Element Plus Dropdown 提供统一的菜单样式和交互

**实施要点**：
- 在 TreeView 组件中监听 `@node-contextmenu` 事件
- 事件处理：
  ```javascript
  (event, data, node, element) => {
    event.preventDefault()
    if (data.type === 'group') {
      // 显示 Dropdown 在鼠标位置
      showContextMenu(event.clientX, event.clientY, data.id)
    }
  }
  ```
- 使用动态定位的 `<el-dropdown>` 或自定义 `ContextMenu` 组件
- 菜单项点击后调用 `store.createGroup(parentId, '新分组')`

**反模式**：
- ❌ 不要使用原生 `contextmenu` 事件（Element Plus 事件更可控）
- ❌ 不要在目录节点或蓝图节点上显示菜单（仅分组节点）

---

### 决策点 5：如何实现自定义节点内容？

**选择**：使用 Element Plus Tree 的 scoped slot `#default="{ node, data }"`

**理由**：scoped slot 提供完整的节点数据和灵活的渲染能力

**实施要点**：
- 在 `<el-tree>` 内定义 `<template #default="{ node, data }">`
- 使用独立的 `TreeNode.vue` 组件处理节点渲染逻辑
- 节点布局使用 Flex：
  ```vue
  <div class="tree-node">
    <el-icon class="node-icon"><!-- 图标 --></el-icon>
    <el-tag v-if="data.isActivated" size="small">已激活</el-tag>
    <div class="node-metadata"><!-- 元数据 --></div>
    <div class="node-toolbox"><!-- 按钮组 --></div>
  </div>
  ```
- CSS 控制布局：
  ```scss
  .tree-node {
    display: flex;
    align-items: center;
    gap: 8px;
    height: 40px;
    padding: 0 12px;
    
    .node-metadata {
      flex: 1;
      max-width: 200px;
      overflow-x: scroll;
      white-space: nowrap;
    }
    
    .node-toolbox {
      margin-left: auto;
    }
  }
  ```

**反模式**：
- ❌ 不要使用 `render-content`（JSX 语法在 Vue 3 + TS 中支持不佳）
- ❌ 不要在节点内放置过多内容（影响性能和可读性）

### 功能验收

**BlueprintSource 模块**：
- ✓ 初始加载显示根级目录节点，不展开子节点
- ✓ 展开目录节点时，调用懒加载函数，显示子节点（延迟 300ms 符合 Mock 设置）

- ✓ 复选框仅在蓝图节点上有效，目录节点复选框禁用

**ActiveBlueprint 模块**：

- ✓ ActiveBlueprint 树中不显示激活/取消激活按钮（这些操作仅在 BlueprintSource 中完成）

### 性能验收

- ✓ 初始加载时间 < 500ms（Mock 数据，10 个根节点）
