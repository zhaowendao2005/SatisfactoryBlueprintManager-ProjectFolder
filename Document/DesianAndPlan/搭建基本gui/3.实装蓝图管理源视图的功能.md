# 蓝图源添加与文件识别功能 - 技术设计方案

## 📋 第一部分：设计概览（必需）

```
【目标】：实现蓝图源的文件夹选择、文件扫描、树结构生成，替换 Mock 数据为实际文件系统数据

【范围】：
  在范围内：
    - Electron 文件夹选择对话框
    - .sbp/.sbpcfg 文件识别与过滤
    - 目录递归遍历（深度 ≤ 5 层）
    - 蓝图源配置文件创建
    - Datasource Mock → 文件系统适配器切换

  
  不在范围内：
    - .sbp 文件内容解析（后续任务）//不需要
    - 蓝图预览功能  //不需要
    - 多源优先级管理  //不需要


【技术栈决策】：
  - 文件对话框：Electron dialog.showOpenDialog（原因：原生系统对话框，用户体验最佳）
  - 文件遍历：Node.js fs.promises + 递归（原因：文件数量 < 500，同步遍历性能可接受）
  - 路径处理：Node.js path 模块（原因：跨平台路径兼容）
  - IPC 通信：Electron contextBridge（原因：安全的渲染进程与主进程通信）
  - 数据持久化：JSON 文件（原因：配置简单，无需数据库）

【架构模式】：分层架构（Renderer ↔ IPC ↔ Main Process ↔ File System）

【核心约束】：
  - 单次扫描目录文件数：≤ 500 个（超过弹出警告）
  - 目录深度限制：≤ 5 层（防止性能问题）
  - 扫描超时时间：10s（超时中断）
  - 支持的文件扩展名：.sbp, .sbpcfg（仅 .sbp 渲染为蓝图节点）
  - 配置文件大小：< 10KB
```

## 🏗️ 第二部分：模块划分与职责（必需）

```
蓝图源管理系统
  ├─ Electron IPC 层（职责：渲染进程与主进程通信桥接）
  │   ├─ 输入：前端调用（selectDirectory, scanDirectory, writeConfig）
  │   ├─ 输出：IPC 响应（selectedPath, scannedTree, writeResult）
  │   └─ 关键逻辑：
  │       1. 定义 IPC channel 名称（blueprint:selectDirectory 等）
  │       2. 在 preload 中通过 contextBridge.exposeInMainWorld 暴露 API
  │       3. 在 main process 中注册 ipcMain.handle 处理器
  │
  ├─ 文件夹选择模块（职责:唤起系统文件选择对话框）
  │   ├─ 输入：void（无参数）
  │   ├─ 输出：{ canceled: boolean, path?: string }
  │   └─ 关键逻辑：
  │       1. 调用 dialog.showOpenDialog({ properties: ['openDirectory'] })
  │       2. 校验选中路径是否有效（fs.access 检查读权限）
  │       3. 返回路径或 canceled 标志
  │
  ├─ 目录扫描模块（职责：递归遍历目录，生成蓝图节点树）
  │   ├─ 输入：{ path: string, maxDepth: number, timeout: number }
  │   ├─ 输出：{ tree: BlueprintNode, fileCount: number, exceededLimit: boolean }
  │   ├─ 依赖：Node.js fs.promises, path
  │   └─ 关键逻辑：
  │       伪代码：
  │       ```
  │       async function scanDirectory(dirPath, currentDepth = 0) {
  │         if (currentDepth > maxDepth) return []
  │         if (fileCount > 500) throw new Error('Too many files')
  │         
  │         entries = await fs.readdir(dirPath, { withFileTypes: true })
  │         nodes = []
  │         
  │         for (entry of entries) {
  │           if (entry.isDirectory()) {
  │             children = await scanDirectory(entry.path, currentDepth + 1)
  │             nodes.push({ type: 'directory', children, ... })
  │           } else if (entry.name.endsWith('.sbp')) {
  │             // 仅处理 .sbp 文件，跳过 .sbpcfg
  │             nodes.push({ type: 'blueprint', path: entry.path, ... })
  │             fileCount++
  │           }
  │         }
  │         
  │         return nodes
  │       }
  │       ```
  │   └─ 错误处理：
  │       - 权限不足：捕获 EACCES，跳过该目录并记录警告
  │       - 超时：使用 Promise.race + setTimeout 实现超时中断
  │       - 文件数超限：抛出异常，前端提示用户
  │
  ├─ 配置文件管理模块（职责：在源路径下创建/读取配置文件）
  │   ├─ 输入：{ sourcePath: string, config: SourceConfig }
  │   ├─ 输出：Promise<void>
  │   └─ 关键逻辑：
  │       1. 配置文件路径 = path.join(sourcePath, 'SatisfactoryBlueprintManager.config.json')
  │       2. 检查文件是否存在（fs.access），存在则合并配置，不存在则创建
  │       3. 写入 JSON（fs.writeFile + JSON.stringify(config, null, 2)）
  │       4. 写入失败时回滚操作（创建 .bak 备份）
  │
  ├─ Datasource 适配器切换（职责：将 Mock 实现替换为文件系统实现）
  │   ├─ 输入：sources: BlueprintSource[]（持久化的源列表）
  │   ├─ 输出：BlueprintNode[]（树根节点）
  │   ├─ 依赖：Electron IPC 层、配置文件管理模块
  │   └─ 关键逻辑：
  │       1. getSources()：从 localStorage 或配置文件读取源列表
  │       2. getRootNodes()：将 sources 转换为根节点数组
  │       3. getChildren(nodeId)：
  │          - 从 nodeId 解析出物理路径
  │          - 调用 IPC scanDirectory（仅扫描一层，lazy loading）
  │          - 缓存结果到内存（避免重复扫描）
  │       4. addSource(source)：
  │          - 调用 IPC selectDirectory 获取路径
  │          - 调用 IPC scanDirectory 验证路径有效性
  │          - 调用 IPC writeConfig 创建配置文件
  │          - 保存 source 到 localStorage
  │
  └─ 前端 Store 改造（职责：适配新的 Datasource 接口）
      ├─ 输入：用户交互（点击"添加源"按钮）
      ├─ 输出：更新 treeData 状态
      └─ 关键逻辑：
          1. handleAddSource()：
             - 调用 datasource.selectDirectory()
             - 用户确认后调用 datasource.addSource()
             - 刷新根节点（调用 loadRootNodes()）
          2. 错误处理：
             - 捕获所有异常并转换为用户友好的错误消息
             - 使用 Element Plus ElMessage 展示错误
```

## 🔌 第三部分：关键接口定义（必需）

```typescript
// ========== 类型定义（public/types/blueprint/index.ts） ==========

/**
 * 蓝图源配置文件结构
 * @注意事项 存储在蓝图源目录下的 SatisfactoryBlueprintManager.config.json
 */
interface SourceConfigFile {
  version: string                  // 配置版本，默认 '1.0.0'
  sourceId: string                 // 源 id（由前端生成）
  sourceName: string               // 源名称（用户输入）
  createdAt: number                // 创建时间戳
  lastScannedAt: number            // 最后扫描时间戳
  metadata?: {
    fileCount?: number             // 蓝图文件数量
    totalSize?: number             // 总大小（字节）
  }
}

/**
 * 目录扫描参数
 */
interface ScanDirectoryParams {
  path: string                     // 目录路径
  maxDepth?: number                // 最大深度，默认 5
  timeout?: number                 // 超时时间（毫秒），默认 10000
}

/**
 * 目录扫描结果
 */
interface ScanDirectoryResult {
  tree: BlueprintNode              // 树根节点
  fileCount: number                // 扫描到的文件数
  exceededLimit: boolean           // 是否超过文件数限制
  warnings: string[]               // 警告信息（如权限不足的目录）
}

/**
 * 文件夹选择结果
 */
interface SelectDirectoryResult {
  canceled: boolean                // 用户是否取消
  path?: string                    // 选中的路径
}

// ========== Electron IPC API 定义（public/types/window/index.ts 扩展） ==========

/**
 * 蓝图相关 Electron IPC API
 * @注意事项 仅在 Electron 环境可用
 */
interface ElectronBlueprintAPI {
  /**
   * 打开文件夹选择对话框
   * @returns Promise<SelectDirectoryResult>
   */
  selectDirectory(): Promise<SelectDirectoryResult>

  /**
   * 扫描目录（递归）
   * @param params 扫描参数
   * @returns Promise<ScanDirectoryResult>
   * @注意事项 超时会抛出 TimeoutError 异常
   */
  scanDirectory(params: ScanDirectoryParams): Promise<ScanDirectoryResult>

  /**
   * 读取单层目录（非递归，用于懒加载）
   * @param dirPath 目录路径
   * @returns Promise<BlueprintNode[]>
   */
  readDirectoryShallow(dirPath: string): Promise<BlueprintNode[]>

  /**
   * 写入配置文件
   * @param sourcePath 源路径
   * @param config 配置对象
   * @returns Promise<void>
   */
  writeSourceConfig(sourcePath: string, config: SourceConfigFile): Promise<void>

  /**
   * 读取配置文件
   * @param sourcePath 源路径
   * @returns Promise<SourceConfigFile | null>
   */
  readSourceConfig(sourcePath: string): Promise<SourceConfigFile | null>
}

declare global {
  interface Window {
    electronAPI?: ElectronWindowAPI
    blueprintAPI?: ElectronBlueprintAPI  // 新增
  }
}

// ========== Datasource 接口扩展（stores/BlueprintSource/types.ts） ==========

interface IBlueprintSourceDatasource {
  // ... 保留原有方法 ...

  /**
   * 选择目录并添加源
   * @注意事项 包含完整流程：选择 → 扫描 → 创建配置 → 保存
   * @throws {Error} 用户取消、目录无效、扫描失败等
   */
  selectAndAddSource(): Promise<BlueprintSource>

  /**
   * 扫描源目录（用于刷新）
   * @param sourceId 源 id
   * @returns Promise<BlueprintNode[]> 更新后的根节点
   */
  rescanSource(sourceId: string): Promise<BlueprintNode[]>
}

## 📊 第四部分：数据流与状态机（必需）

```
数据流向：
  [用户点击"添加源"]
    --(触发 handleAddSource)--> 
  [Store: useBlueprintSourceStore]
    --(调用 datasource.selectAndAddSource())--> 
  [Datasource]
    --(IPC: blueprintAPI.selectDirectory())--> 
  [Electron Main Process]
    --(调用 dialog.showOpenDialog)--> 
  [系统文件对话框]
    --(用户选择路径 path)--> 
  [Electron Main Process]
    --(IPC 返回 { canceled: false, path })--> 
  [Datasource]
    --(IPC: blueprintAPI.scanDirectory({ path }))--> 
  [Electron Main Process: 文件扫描模块]
    --(递归遍历 fs.readdir)--> 
  [生成 BlueprintNode[] 树结构]
    --(IPC 返回 ScanDirectoryResult)--> 
  [Datasource]
    --(IPC: blueprintAPI.writeSourceConfig(path, config))--> 
  [Electron Main Process]
    --(写入 SatisfactoryBlueprintManager.config.json)--> 
  [Datasource]
    --(保存 source 到 localStorage)--> 
  [Datasource]
    --(返回 BlueprintSource)--> 
  [Store]
    --(更新 sources, treeData)--> 
  [Vue 组件自动重新渲染]

蓝图源添加状态机：
  IDLE（空闲）
    -> [点击"添加源"] -> SELECTING（选择中）
  
  SELECTING（选择中）
    -> [用户取消] -> IDLE（返回空闲）
    -> [选择成功] -> SCANNING（扫描中）
  
  SCANNING（扫描中）
    -> [扫描超时] -> ERROR（显示错误提示）-> IDLE
    -> [文件数超限] -> WARNING（显示警告，询问是否继续）-> SCANNING
    -> [扫描成功] -> CREATING_CONFIG（创建配置）
  
  CREATING_CONFIG（创建配置）
    -> [写入失败] -> ERROR（显示错误提示）-> IDLE
    -> [写入成功] -> SAVING（保存到 Store）
  
  SAVING（保存到 Store）
    -> [保存成功] -> SUCCESS（显示成功提示）-> IDLE
    -> [保存失败] -> ERROR（显示错误提示）-> IDLE

懒加载数据流（点击目录节点展开时）：
  [用户展开目录节点]
    --(el-tree 触发 loadNode)--> 
  [TreeView: loadNode 函数]
    --(调用 store.loadChildren(nodeId))--> 
  [Store]
    --(调用 datasource.getChildren(nodeId))--> 
  [Datasource]
    --(从 nodeId 解析出物理路径)--> 
  [检查内存缓存]
    -> 有缓存: 直接返回
    -> 无缓存: 调用 IPC blueprintAPI.readDirectoryShallow(dirPath)
  [Electron Main Process]
    --(fs.readdir 单层遍历)--> 
  [返回 BlueprintNode[]]
    --(缓存到 Datasource 内存)--> 
  [返回给 Store]
    --(Store 更新 treeData)--> 
  [resolve(children) 触发 el-tree 渲染]
```

## ⚠️ 第五部分:关键决策点与实施注意事项（必需）

```
决策点 1：如何组织文件节点的唯一 id？
  选择：使用完整的文件系统路径作为 id（如 "D:/blueprints/源1/文件夹A/蓝图1.sbp"）
  理由：
    - 保证全局唯一性（文件路径不会重复）
    - 懒加载时可以直接从 id 解析出物理路径，无需额外映射表
    - 跨源蓝图不会冲突（不同源的路径不同）
  实施要点：
    - Windows 路径统一转换为正斜杠（path.normalize + replace('\\', '/')）
    - 对于非文件节点（如源根节点），使用 sourceId 作为 id
    - 蓝图节点 id 格式：完整文件路径（含 .sbp 扩展名）
  反模式：
    ❌ 不要使用相对路径（无法保证唯一性）
    ❌ 不要使用文件名作为 id（可能重复）

决策点 2：目录扫描是全量扫描还是懒加载？
  选择：混合策略 - 添加源时全量扫描（构建完整树），展开节点时使用缓存
  理由：
    - 蓝图目录通常不深（1-3 层），全量扫描耗时可接受（< 2s）
    - 全量扫描可以立即获得文件数统计（用于警告提示）
    - el-tree 需要 isLeaf 属性判断是否展开，全量扫描后可准确设置
  实施要点：
    - 添加源时：调用 scanDirectory 递归扫描，设置 maxDepth=5
    - 首次渲染：使用扫描结果，无需 lazy loading
    - 展开节点：从缓存读取，缓存失效时调用 readDirectoryShallow
    - 刷新源：清除缓存，重新全量扫描
  反模式：
    ❌ 不要纯懒加载（无法提前判断文件数）
    ❌ 不要每次展开都重新扫描（性能浪费）

决策点 3：配置文件何时创建？
  选择：用户选择目录后、扫描成功后立即创建
  理由：
    - 标记该目录已被本应用管理（避免重复添加）
    - 存储扫描时间戳（用于后续增量更新）
    - 预留扩展空间（未来可存储用户自定义元数据）
  实施要点：
    - 文件名固定：SatisfactoryBlueprintManager.config.json
    - 创建前检查是否已存在：存在则读取并合并（保留 createdAt）
    - 写入失败不阻塞添加源流程（仅记录警告）
    - sourceId 由前端生成（`source-${Date.now()}-${Math.random()}`）
  反模式：
    ❌ 不要在用户配置目录（AppData）存储，必须在源目录下（便于备份/迁移）
    ❌ 不要使用隐藏文件（Windows 用户可能看不到）

决策点 4：.sbpcfg 文件如何处理？
  选择：扫描时识别但不渲染，仅在解析 .sbp 时读取对应的 .sbpcfg
  理由：
    - 用户只关心蓝图本身，不关心配置文件
    - .sbpcfg 和 .sbp 是 1:1 关系，合并展示更直观
    - 减少树节点数量（每个蓝图 1 个节点而非 2 个）
  实施要点：
    - 扫描时跳过 .sbpcfg 文件（if (!entry.name.endsWith('.sbp')) continue）
    - 解析 .sbp 时自动查找同名 .sbpcfg（path.basename(sbpPath, '.sbp') + '.sbpcfg'）
    - 如果 .sbpcfg 不存在，使用默认配置
  反模式：
    ❌ 不要将 .sbpcfg 渲染为独立节点
    ❌ 不要在扫描时解析 .sbpcfg 内容（延迟到需要时解析）

决策点 5：如何实现跨平台路径兼容？
  选择：统一使用 Node.js path 模块 + 路径规范化
  理由：
    - path 模块自动处理平台差异（Windows / vs Unix \）
    - 避免手工字符串拼接导致的路径错误
  实施要点：
    - 所有路径拼接使用 path.join()
    - 路径比较前使用 path.normalize()
    - 存储路径时统一转换为正斜杠（replace(/\\/g, '/')）
    - 传递给 Node.js API 前使用 path.resolve() 转为绝对路径
  反模式：
    ❌ 不要使用字符串拼接（`${dir}/${file}`）
    ❌ 不要硬编码路径分隔符（'\\' 或 '/'）

决策点 6：文件数超限如何处理？
  选择：扫描到 500 个文件时中断，弹出警告，用户选择继续或取消
  理由：
    - 保护性能（超大目录会导致渲染卡顿）
    - 给用户选择权（可能确实需要大目录）
  实施要点：
    - 扫描器维护 fileCount 变量，每发现 1 个 .sbp 文件 +1
    - fileCount 达到 500 时抛出 FileLimitExceeded 异常
    - 前端捕获异常，显示 ElMessageBox 询问
    - 用户确认后重新调用，传递 ignoreLimit: true 标志
  反模式：
    ❌ 不要静默截断（用户不知道发生了什么）
    ❌ 不要完全禁止大目录（用户可能有合理需求）
```

## 🧪 第六部分：验收标准（必需）

```
功能验收：
  ✓ 点击"添加源"按钮，弹出系统文件选择对话框
  ✓ 选择包含 100 个 .sbp 文件的目录，2s 内完成扫描并渲染树结构
  ✓ 树结构中仅显示 .sbp 文件为蓝图节点，.sbpcfg 不可见
  ✓ 目录节点可展开/折叠，展开时自动加载子节点（懒加载）
  ✓ 扫描完成后，在源目录下生成 SatisfactoryBlueprintManager.config.json
  ✓ 配置文件包含 sourceId, createdAt, lastScannedAt 字段
  ✓ 重复添加同一目录时，读取已有配置文件，保留 createdAt
  ✓ 刷新源后，树结构更新为最新文件列表

性能验收：
  ✓ 扫描 100 个文件（3 层目录）耗时 < 2s（测量环境：SSD 硬盘）
  ✓ 扫描 500 个文件（5 层目录）耗时 < 10s
  ✓ 渲染 100 个节点的树耗时 < 500ms（Chrome DevTools Performance 测量）
  ✓ 懒加载单层目录（20 个文件）耗时 < 100ms
  ✓ 内存占用：100 个文件 < 10MB，500 个文件 < 50MB

边界条件验收：
  ✓ 选择空目录，扫描结果为空数组，提示"未发现蓝图文件"
  ✓ 选择仅包含 .sbpcfg 文件的目录，提示"未发现蓝图文件"

  ✓ 文件数超过 500，弹出警告"文件过多，可能影响性能，是否继续？"
  ✓ 用户取消文件选择，不执行任何操作，返回原界面
  ✓ 配置文件写入失败（磁盘满、权限不足），不阻塞添加源，记录警告日志
  ✓ 扫描中删除文件，扫描继续，跳过已删除文件
  ✓ 扫描中修改文件，扫描基于快照，不受影响
  ✓ Windows 路径（C:\Users\...）和 Unix 路径（/home/...）均正常工作

类型安全验收：
  ✓ 所有 IPC 调用有完整的 TypeScript 类型定义
  ✓ ESLint 无类型错误
  ✓ 使用 `import type` 导入类型（符合 ESLint 规则）
  ✓ 所有 public API 有 JSDoc 注释

## 🔀 第七部分：文件修改清单
