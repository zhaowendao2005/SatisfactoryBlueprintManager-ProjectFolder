蓝图源批量激活优化与重复蓝图标识功能设计方案

## 📋 第一部分：设计概览

**【目标】**：优化蓝图源的批量激活逻辑，支持懒加载目录的深度遍历，并为重复激活的蓝图添加视觉标识

**【范围】**：
- **在范围内**：
  - 懒加载目录节点的深度遍历与子节点自动加载
  - 批量激活时保留源目录结构
  - 基于蓝图物理路径的重复检测算法
  - 重复蓝图的彩色圆点标识系统
  - 颜色分配与一致性维护机制
- **不在范围内**：
  - 单个蓝图激活逻辑的修改（已有实现）
  - 蓝图源的扫描和索引机制（已有实现）
  - 激活蓝图的同步功能（已有实现）

**【技术栈决策】**：
- **深度遍历**：递归 + Promise.all（原因：需要并发加载多个目录的子节点，提升性能）
- **重复检测**：Map<sourcePath, string[]>（原因：sourcePath 作为物理路径唯一标识，数组存储所有激活节点 id）
- **颜色分配**：预定义色板 + HSL 动态生成（原因：少量重复用预定义颜色，大量重复时自动生成区分度高的颜色）
- **状态管理**：扩展 ActiveBlueprintStore（原因：重复检测状态需要与树数据同步维护）
- **UI 组件**：扩展 ActiveBlueprint/TreeNode.vue（原因：圆点标识是节点的视觉扩展）

**【架构模式】**：
- **数据处理层**：递归遍历 + 异步加载（Store actions 层）
- **状态同步层**：响应式状态 + computed 派生（Pinia reactivity）
- **视图渲染层**：条件渲染 + 动态样式（Vue template + scoped CSS）

**【核心约束】**：
- **深度遍历性能**：单次批量激活的目录深度遍历 < 5s（假设目录层级 ≤ 10，每层节点 ≤ 100）
- **并发控制**：懒加载子节点的并发数 ≤ 5（避免过多 IPC 调用导致主进程阻塞）
- **颜色数量**：预定义色板 10 个颜色，超过则 HSL 动态生成（H 步长 = 360 / (count - 10)）
- **重复检测复杂度**：O(n)，n = 已激活蓝图节点总数
- **圆点尺寸**：直径 8px，与 title 右侧间距 8px

## 🏗️ 第二部分：模块划分与职责

```
批量激活增强系统
├─ 深度遍历加载器（DeepTraversalLoader）
│   ├─ 职责：检测并深度加载未加载的目录节点
│   ├─ 输入：checkedKeys: string[]（选中的节点 id 列表）
│   ├─       sourceTree: BlueprintNode[]（蓝图源树根节点）
│   ├─       store: BlueprintSourceStore（提供 loadChildren 方法）
│   ├─ 输出：LoadedNodesResult { 
│   │         fullyLoadedKeys: string[]  // 完全加载后的所有蓝图节点 id
│   │         loadedDirectories: Map<string, BlueprintNode> // 已加载的目录节点映射
│   │       }
│   └─ 关键逻辑：
│       1. 遍历 checkedKeys，区分蓝图节点和目录节点
│       2. 对目录节点：
│          a. 检查 children 是否为 undefined（未加载标志）
│          b. 如果未加载，调用 store.loadChildren(nodeId)
│          c. 递归检查子节点，重复步骤 2
│       3. 使用 Promise.all + 并发控制（p-limit，concurrency=5）
│       4. 收集所有蓝图节点 id 到 fullyLoadedKeys
│       5. 返回结果
│
├─ 增强智能分组构建器（EnhancedGroupBuilder）
│   ├─ 职责：基于完全加载的节点构建分组结构，保留源目录层级
│   ├─ 输入：fullyLoadedKeys: string[]（所有蓝图节点 id）
│   ├─       sourceTree: BlueprintNode[]（蓝图源树）
│   ├─       loadedDirectories: Map<string, BlueprintNode>（已加载的目录节点）
│   ├─ 输出：GroupStructure {
│   │         groups: ActiveBlueprintNode[]  // 分组节点（包含子目录和蓝图）
│   │         ungrouped: ActiveBlueprintNode[] // 未分组蓝图
│   │       }
│   └─ 关键逻辑：
│       1. 遍历 fullyLoadedKeys，对每个蓝图节点：
│          a. 回溯其父目录路径（从 loadedDirectories 查找）
│          b. 构建从根目录到该蓝图的完整层级结构
│          c. 合并到 groups 的树结构中（去重相同目录）
│       2. 对于选中的单个蓝图（无父目录在 checkedKeys 中）：
│          添加到 ungrouped
│       3. 生成 ActiveBlueprintNode 节点：
│          - 目录节点：type='group', name=目录名, children=[]
│          - 蓝图节点：type='blueprint', sourcePath=物理路径, blueprintId=原始id
│       4. 返回结构化结果
│
├─ 重复蓝图检测器（DuplicateDetector）
│   ├─ 职责：检测已激活蓝图中的重复项（按 sourcePath 判断）
│   ├─ 输入：treeData: ActiveBlueprintNode[]（已激活蓝图树）
│   ├─ 输出：DuplicateMap = Map<sourcePath: string, nodeIds: string[]>
│   │        // key: 蓝图物理路径, value: 所有激活该蓝图的节点 id 列表
│   └─ 关键逻辑：
│       1. 初始化 Map<sourcePath, string[]>
│       2. 递归遍历 treeData：
│          a. 如果节点类型为 'blueprint' 且有 sourcePath：
│             - 将 node.id 添加到 map.get(sourcePath) 数组中
│          b. 如果节点类型为 'group'：
│             - 递归处理 children
│       3. 过滤 map，仅保留 value.length > 1 的条目（真正重复的）
│       4. 返回 DuplicateMap
│
├─ 颜色分配器（ColorAllocator）
│   ├─ 职责：为重复的蓝图分配唯一且一致的颜色
│   ├─ 输入：duplicateMap: DuplicateMap
│   ├─ 输出：ColorMap = Map<sourcePath: string, color: string>
│   │        // key: 蓝图物理路径, value: CSS 颜色值（hex 或 hsl）
│   └─ 关键逻辑：
│       1. 定义预设色板（10个）：
│          ['#FF6B6B', '#4ECDC4', '#45B7D1', '#FFA07A', '#98D8C8',
│           '#F7DC6F', '#BB8FCE', '#85C1E2', '#F8B739', '#52B788']
│       2. 获取 duplicateMap 的 keys 并排序（保证一致性）
│       3. 遍历 keys：
│          a. 如果 index < 10：使用预设色板[index]
│          b. 否则：HSL 动态生成
│             - H = (index - 10) * (360 / (totalCount - 10))
│             - S = 70%, L = 60%
│             - 转换为 CSS hsl(H, S%, L%)
│       4. 返回 ColorMap
│
└─ 视图层圆点渲染器（DotRenderer）
    ├─ 职责：在 TreeNode 组件中渲染重复标识圆点
    ├─ 输入：nodeData: ActiveBlueprintNode（当前节点数据）
    ├─       colorMap: ColorMap（颜色映射表，从 store computed）
    ├─       duplicateMap: DuplicateMap（重复映射表，从 store computed）
    ├─ 输出：渲染的 DOM 元素（条件渲染）
    └─ 关键逻辑：
        1. 检查 nodeData.type === 'blueprint' && nodeData.sourcePath
        2. 从 colorMap 查询 color = colorMap.get(nodeData.sourcePath)
        3. 如果 color 存在：
           渲染 <span class="duplicate-dot" :style="{ backgroundColor: color }"></span>
        4. 否则：不渲染任何内容
        5. CSS 样式：
           .duplicate-dot {
             display: inline-block;
             width: 8px;
             height: 8px;
             border-radius: 50%;
             margin-left: 8px;
             flex-shrink: 0;
           }
```

## 🔌 第三部分：关键接口定义

```typescript
/**
 * 深度遍历加载器的返回结果
 * @注意事项 fullyLoadedKeys 仅包含蓝图节点 id，不包含目录节点
 */
interface LoadedNodesResult {
  fullyLoadedKeys: string[]                    // 完全加载后的所有蓝图节点 id
  loadedDirectories: Map<string, BlueprintNode> // 已加载的目录节点（key=nodeId）
}

/**
 * 增强智能分组构建器的返回结果
 * @注意事项 groups 中的分组节点可能包含多层嵌套（保留源目录结构）
 */
interface GroupStructure {
  groups: ActiveBlueprintNode[]     // 分组节点（包含子目录和蓝图）
  ungrouped: ActiveBlueprintNode[]  // 未分组蓝图（选中单个蓝图无父目录时）
}

/**
 * 重复蓝图映射表
 * @注意事项 
 * - key 为蓝图的物理路径（sourcePath）
 * - value 为所有激活该蓝图的节点 id 数组
 * - 仅包含 length > 1 的条目（真正重复的）
 */
type DuplicateMap = Map<string, string[]>

/**
 * 颜色映射表
 * @注意事项 颜色值为 CSS 兼容格式（hex 或 hsl）
 */
type ColorMap = Map<string, string>

/**
 * ActiveBlueprintStore 扩展状态
 */
interface ActiveBlueprintState {
  // ... 现有状态 ...
  duplicateMap: DuplicateMap  // 重复蓝图映射表（响应式）
  colorMap: ColorMap          // 颜色映射表（响应式）
}

/**
 * ActiveBlueprintStore 扩展 Actions
 */
interface ActiveBlueprintStoreActions {
  /**
   * 批量激活蓝图（增强版，支持懒加载目录深度遍历）
   * @param checkedKeys 选中的节点 id 列表（包含蓝图和目录）
   * @param sourceTree 蓝图源树根节点
   * @注意事项 
   * - 自动检测并加载未加载的目录节点
   * - 保留源目录层级结构
   * - 加载完成后自动更新 duplicateMap 和 colorMap
   */
  batchActivateBlueprintsEnhanced(
    checkedKeys: string[],
    sourceTree: BlueprintNode[]
  ): Promise<void>

  /**
   * 深度遍历并加载目录节点（私有方法）
   * @param checkedKeys 选中的节点 id 列表
   * @param sourceTree 蓝图源树根节点
   * @param store BlueprintSourceStore 实例
   * @returns LoadedNodesResult 加载结果
   * @注意事项 并发控制为 5，避免过多 IPC 调用
   */
  deepTraverseAndLoad(
    checkedKeys: string[],
    sourceTree: BlueprintNode[],
    store: BlueprintSourceStore
  ): Promise<LoadedNodesResult>

  /**
   * 构建增强分组结构（私有方法）
   * @param fullyLoadedKeys 完全加载后的蓝图节点 id 列表
   * @param sourceTree 蓝图源树
   * @param loadedDirectories 已加载的目录节点映射
   * @returns GroupStructure 分组结构
   */
  buildEnhancedGroupStructure(
    fullyLoadedKeys: string[],
    sourceTree: BlueprintNode[],
    loadedDirectories: Map<string, BlueprintNode>
  ): GroupStructure

  /**
   * 更新重复检测映射（私有方法）
   * @注意事项 
   * - 每次 treeData 变化后调用
   * - 自动更新 duplicateMap 和 colorMap
   */
  updateDuplicateDetection(): void

  /**
   * 检测重复蓝图（私有方法）
   * @param treeData 已激活蓝图树
   * @returns DuplicateMap 重复映射表
   */
  detectDuplicates(treeData: ActiveBlueprintNode[]): DuplicateMap

  /**
   * 分配颜色（私有方法）
   * @param duplicateMap 重复映射表
   * @returns ColorMap 颜色映射表
   */
  allocateColors(duplicateMap: DuplicateMap): ColorMap
}

/**
 * ActiveBlueprint/TreeNode.vue Props 扩展
 */
interface TreeNodeProps {
  node: Record<string, unknown>  // Element Plus TreeNode 对象
  data: ActiveBlueprintNode      // 节点数据
  // 新增：重复标识颜色（从 store computed 传入）
  duplicateColor?: string        // 如果该蓝图重复，传入对应颜色；否则 undefined
}
```

## 📊 第四部分：数据流与状态机

### 数据流向

```
[用户勾选节点（包含目录）]
  --(checkedKeys: string[])--> 
[TreeView handleBatchActivate]
  --(checkedKeys + sourceTree)--> 
[BlueprintSourceStore.batchActivateBlueprints]
  --(传递)--> 
[ActiveBlueprintStore.batchActivateBlueprintsEnhanced]
  |
  ├─ [deepTraverseAndLoad] 
  │    --(递归懒加载)--> 
  │  [BlueprintSourceStore.loadChildren (IPC调用)]
  │    --(LoadedNodesResult)--> 
  │  返回到主流程
  │
  ├─ [buildEnhancedGroupStructure]
  │    --(构建层级结构)--> 
  │  返回 GroupStructure
  │
  ├─ [合并到 treeData]
  │    --(更新状态)--> 
  │  store.treeData
  │
  ├─ [updateDuplicateDetection]
  │    --(检测重复)--> 
  │  [detectDuplicates] --> DuplicateMap
  │    --(分配颜色)--> 
  │  [allocateColors] --> ColorMap
  │    --(更新状态)--> 
  │  store.duplicateMap, store.colorMap
  │
  └─ [saveCurrentConfig]
       --(持久化)--> 
     [本地配置文件]

[TreeView 渲染]
  <-- (treeData) --
[ActiveBlueprintStore]

[TreeNode 渲染]
  <-- (data, duplicateColor) --
[Computed: colorMap.get(data.sourcePath)]

[Dot 条件渲染]
  <-- (duplicateColor 存在？) --
[TreeNode Template]
```

### 状态变化时序

```
Time 0: 用户勾选节点（2个蓝图 + 1个未加载的目录）
Time 1: 触发 handleBatchActivate
Time 2: deepTraverseAndLoad 开始
Time 3: 检测到目录未加载，调用 loadChildren（IPC）
Time 4: 并发加载目录的子节点（可能包含子目录）
Time 5: 递归检测子目录，继续加载（最多10层）
Time 6: 所有蓝图节点收集完毕，返回 LoadedNodesResult
Time 7: buildEnhancedGroupStructure 构建层级结构
Time 8: 合并到 treeData，保留目录嵌套关系
Time 9: updateDuplicateDetection 检测重复
Time 10: 如果有重复，分配颜色，更新 colorMap
Time 11: TreeView 重新渲染，TreeNode 显示圆点
```

## ⚠️ 第五部分：关键决策点与实施注意事项

### 决策点 1：如何判断目录节点是否已加载？

**选择**：检查 `node.children === undefined`（而非 `null` 或 `[]`）

**理由**：
- Element Plus Tree 的懒加载约定：`children: undefined` 表示未加载
- `children: []` 表示已加载但为空目录
- 这是 El-Tree 官方文档的标准模式

**实施要点**：
- 在 `deepTraverseAndLoad` 中，判断条件为：
  ```typescript
  if (node.type === 'directory' && node.children === undefined)
  ```
- 加载后，即使子节点为空，也应设置 `node.children = []`

**反模式**：
- ❌ 不要用 `!node.children`（会将 `[]` 误判为未加载）
- ❌ 不要用 `node.children?.length === 0`（无法区分未加载和空目录）

---

### 决策点 2：深度遍历的并发控制如何实现？

**选择**：使用 `p-limit` 库，设置 `concurrency = 5`

**理由**：
- IPC 调用（loadChildren）是性能瓶颈
- 过多并发会阻塞 Electron 主进程
- 5 个并发是经验值（平衡速度与稳定性）

**实施要点**：
- 安装依赖：`p-limit@^4.0.0`（ESM 版本，支持 TypeScript）
- 使用方式：
  ```typescript
  import pLimit from 'p-limit'
  
  const limit = pLimit(5)
  const tasks = directories.map(dir =>
    limit(() => store.loadChildren(dir.id))
  )
  const results = await Promise.all(tasks)
  ```
- 递归时复用同一个 `limit` 实例

**反模式**：
- ❌ 不要用 `Promise.all` 无限并发（会导致 IPC 队列堆积）
- ❌ 不要用 `for...await`串行（速度太慢）

---

### 决策点 3：如何保留源目录的层级结构？

**选择**：回溯蓝图节点的父目录路径，构建嵌套的 `ActiveBlueprintNode` 树

**理由**：
- 用户勾选目录时，期望保留完整的目录结构
- 扁平化会丢失层级信息，不利于后续管理

**实施要点**：
- 在 `buildEnhancedGroupStructure` 中：
  1. 对每个蓝图节点，从 `loadedDirectories` 回溯父目录路径
  2. 构建从根目录到该蓝图的完整层级：
     ```typescript
     // 示例：蓝图路径为 /root/dir1/dir2/blueprint.sbp
     // 构建结构：
     {
       name: 'dir1',
       type: 'group',
       children: [
         {
           name: 'dir2',
           type: 'group',
           children: [
             { name: 'blueprint', type: 'blueprint', ... }
           ]
         }
       ]
     }
     ```
  3. 合并相同目录（去重）：使用 Map<dirPath, ActiveBlueprintNode>

**反模式**：
- ❌ 不要将所有蓝图扁平化到一个分组（丢失层级）
- ❌ 不要创建重复的目录节点（应合并相同路径的目录）

---

### 决策点 4：重复蓝图的 `sourcePath` 如何提取？

**选择**：使用 `node.sourcePath || node.path`（优先 `sourcePath`）

**理由**：
- `sourcePath` 是蓝图的物理路径（在激活时记录）
- `path` 是激活后的路径（可能在不同分组下）
- 重复判断必须基于物理路径，而非激活后的逻辑路径

**实施要点**：
- 在 `activateBlueprint` 时，确保记录 `sourcePath`：
  ```typescript
  const activeNode: ActiveBlueprintNode = {
    id: `active-${Date.now()}-${Math.random()}`,
    type: 'blueprint',
    name: blueprintNode.name,
    path: blueprintNode.path,  // 激活后的路径
    sourcePath: blueprintNode.path,  // 物理路径（用于重复检测）
    blueprintId: blueprintNode.id,
  }
  ```
- 在 `detectDuplicates` 中，判断条件：
  ```typescript
  const sourcePath = node.sourcePath || node.path
  if (sourcePath) {
    map.set(sourcePath, [...(map.get(sourcePath) || []), node.id])
  }
  ```

**反模式**：
- ❌ 不要用 `node.name` 判断重复（可能同名但不同文件）
- ❌ 不要用 `node.id` 判断（激活后 id 是新生成的）

---

### 决策点 5：颜色分配的一致性如何保证？

**选择**：对 `duplicateMap.keys()` 排序后顺序分配颜色

**理由**：
- 相同 `sourcePath` 每次计算都应得到相同颜色
- 排序保证顺序稳定性（即使 Map 内部顺序可能变化）

**实施要点**：
- 在 `allocateColors` 中：
  ```typescript
  const sortedPaths = Array.from(duplicateMap.keys()).sort()
  const colorMap = new Map<string, string>()
  
  sortedPaths.forEach((path, index) => {
    if (index < 10) {
      colorMap.set(path, PRESET_COLORS[index])
    } else {
      const hue = (index - 10) * (360 / (sortedPaths.length - 10))
      colorMap.set(path, `hsl(${hue}, 70%, 60%)`)
    }
  })
  ```

**反模式**：
- ❌ 不要用随机颜色（每次刷新都会变）
- ❌ 不要用 `Math.random()` 生成（无法保证一致性）

---

### 决策点 6：何时触发 `updateDuplicateDetection`？

**选择**：在 `treeData` 变化后立即调用（批量激活、移动节点、删除节点）

**理由**：
- `duplicateMap` 和 `colorMap` 必须与 `treeData` 保持同步
- 响应式更新保证 UI 实时反映重复状态

**实施要点**：
- 在以下 actions 结尾调用 `updateDuplicateDetection()`：
  - `batchActivateBlueprintsEnhanced`（批量激活后）
  - `moveNode` / `moveNodes`（移动节点后）
  - `removeActivatedBlueprint`（删除节点后）
  - `createGroup`（如果涉及节点移动）
- 使用 Pinia 的响应式，自动触发 TreeNode 重新渲染

**反模式**：
- ❌ 不要手动在每个 TreeNode 中计算（性能差）
- ❌ 不要用 watch 监听 treeData（过度响应，影响性能）

## 🧪 第六部分：验收标准

### 功能验收：

✓ **场景1**：勾选3个已加载的蓝图节点，批量激活后，所有3个蓝图出现在激活列表中

✓ **场景2**：勾选1个未加载的目录节点（包含5个蓝图），批量激活后：
  - 自动加载目录内容
  - 所有5个蓝图出现在激活列表中
  - 激活列表中保留该目录的分组结构

✓ **场景3**：勾选1个未加载的多层嵌套目录（3层，共8个蓝图），批量激活后：
  - 递归加载所有子目录（最多10层）
  - 所有8个蓝图出现在激活列表中
  - 激活列表中保留3层嵌套的目录结构

✓ **场景4**：同一个蓝图（sourcePath 相同）被激活2次到不同分组：
  - 两个激活节点右侧都显示相同颜色的圆点
  - 圆点颜色从预设色板中分配（前10个重复）

✓ **场景5**：15个不同蓝图各被重复激活2次：
  - 前10个使用预设色板颜色
  - 后5个使用 HSL 动态生成的颜色
  - 所有颜色互不重复，区分度高

✓ **场景6**：删除其中一个重复蓝图后，另一个重复蓝图的圆点消失（因为不再重复）

### 性能验收：

✓ 深度遍历并加载1个包含50个蓝图的目录（3层嵌套），总耗时 < 3s（Chrome DevTools Network 测量）

✓ 深度遍历并加载5个并发目录（每个10个蓝图），总耗时 < 5s

✓ 检测100个已激活蓝图中的重复项（10个重复），检测耗时 < 100ms（console.time 测量）

✓ 分配15个颜色（10个预设 + 5个动态），分配耗时 < 10ms

✓ TreeNode 渲染1000个节点（100个带圆点），首次渲染耗时 < 500ms（Vue Devtools 测量）

### 边界条件验收：

✓ 勾选的目录节点为空（children = []），批量激活后不添加任何蓝图，不报错

✓ 勾选的目录节点包含子目录但无蓝图，批量激活后仅创建目录分组（空），不报错

✓ 深度遍历超过10层时，停止递归，记录 warning 日志

✓ IPC 调用 loadChildren 失败（网络错误），捕获异常，显示错误提示，已加载的部分不受影响

✓ 同时勾选父目录和子蓝图，去重后不重复激活同一蓝图

✓ 圆点颜色在深色主题下可见（对比度 ≥ 4.5:1，WCAG AA 标准）
